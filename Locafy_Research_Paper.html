Locafy: An Open-Source, Zero-Cost Geospatial Framework for Hyperlocal Small Business Discovery in Developing Digital Economies
Raj Thakur1, Technical Research Team2
Department of Computer Science & Engineering
Mini Project Academic Publication Series, 2026
Abstract— In emerging economies such as India, micro, small, and medium enterprises (MSMEs) face severe economic and technological barriers to digital discoverability. High subscription fees and commissions charged by commercial aggregation monopolies, coupled with compounding metering fees from proprietary mapping APIs (e.g., Google Maps Platform, Places API), make independent local directory solutions financially unviable. This paper presents Locafy, a production-ready, zero-cost hyperlocal business discovery and lead attribution web application built specifically for Indian commercial hubs. Locafy eliminates all proprietary third-party API dependencies by integrating OpenStreetMap (OSM) spatial tiles, Leaflet GIS client rendering, and browser-native W3C Geolocation. At its computational core, the platform introduces a dual-phase query processing engine: (1) an optimized spherical trigonometry Haversine distance calculator paired with bounded SQL spatial pruning, and (2) a real-time temporal operating availability evaluator calibrated to Asia/Kolkata (IST, UTC+05:30) time. The backend implements a resilient database adapter that transparently leverages Node.js v22+ native node:sqlite (DatabaseSync) with automated fallback to better-sqlite3, eliminating external native compilation toolchains. Evaluated over an authentic dataset comprising 49 verified commercial stores across 13 major Indian metropolitan regions, the system achieves sub-15ms query execution times, a 73.9% payload reduction via static asset decoupling, and 100% deterministic pass rates across end-to-end multi-actor verification cycles.
Keywords— Hyperlocal Discovery, Geospatial Information Systems (GIS), Haversine Formula, Zero-Cost Architecture, OpenStreetMap, Leaflet.js, Lead Attribution, SQLite, Indian MSMEs.

1. Introduction

India's domestic retail and service economy comprises over 63 million micro, small, and medium enterprises (MSMEs), representing the primary livelihood source for over 110 million citizens and contributing upwards of 30% to national gross domestic product. While rapid digital penetration via the Unified Payments Interface (UPI) and subsidized 4G/5G mobile connectivity has integrated consumers into the digital financial ecosystem, consumer discovery of neighborhood businesses remains severely centralized.

Commercial directory conglomerates and food-delivery aggregators exploit this asymmetry by imposing steep onboarding charges, per-lead paywalls, and high commission rates (18% to 30%). Simultaneously, independent developers, municipal organizations, or college project initiatives seeking to build open, community-oriented local directories are hindered by compounding cloud API metering tariffs. For example, the Google Maps Platform levies $5.00 to $7.00 per 1,000 Dynamic Map loads and $17.00 per 1,000 Nearby Search requests.

To address this dilemma, this paper presents Locafy, a zero-cost, open-architecture local business discovery and lead attribution platform designed specifically for the unique geographical and commercial landscape of India. Locafy operates end-to-end without paid external API keys, commercial database hosts, or heavyweight JavaScript frameworks.

2. Related Work and Theoretical Foundations

Geographic Information Systems (GIS) for local business search historically rely on client-server spatial querying over spatial indexes such as R-Trees or Geohashes. While modern spatial databases like PostgreSQL with PostGIS offer sophisticated planar and spheroidal operations, they demand dedicated database server daemons with non-trivial memory overhead.

In lightweight or embedded server contexts, SQLite provides an ideal zero-configuration, single-file relational engine. By formulating spherical geodesic equations directly within standard SQL and procedural runtime layers, high-throughput spatial querying is achievable without specialized spatial extensions.

3.1 Resilient Database Driver Abstraction

Standard Node.js deployments on Windows or minimal Linux environments frequently fail when compiling native SQLite bindings (such as better-sqlite3) due to missing Python, Visual Studio C++ Build Tools, or node-gyp dependencies. Locafy resolves this vulnerability by implementing an automated driver detection adapter:

If better-sqlite3 is present, it is utilized synchronously; otherwise, the runtime seamlessly falls back to the native Node.js v22 standard library node:sqlite module (DatabaseSync). The wrapper normalizes argument spreading, PRAGMA journal configurations, and statement execution semantics, guaranteeing 100% turnkey startup on any modern Node.js environment without external compilation steps.

4. Mathematical & Algorithmic Formulations

4.1 Spherical Geodesic Distance via Haversine Formulation

Given a client's detected coordinate pair $(phi_1, lambda_1)$ and a candidate business coordinate pair $(phi_2, lambda_2)$, where $phi$ denotes latitude and $lambda$ denotes longitude in radians:

Deltaphi = ( ext{lat}_2 - ext{lat}_1) cdot rac{pi}{180}, quad Deltalambda = ( ext{lng}_2 - ext{lng}_1) cdot rac{pi}{180} (1)

The square of the half-chord length between the two points is calculated as:

a = sin^2left( rac{Deltaphi}{2} ight) + cos(phi_1) cdot cos(phi_2) cdot sin^2left( rac{Deltalambda}{2} ight) (2)

The angular distance in radians $c$ and resultant surface distance $d$ (using Earth's volumetric radius $R = 6371.0 ext{ km}$) are:

c = 2 cdot ext{atan2}left(sqrt{a}, sqrt{1 - a} ight) (3)
d = R cdot c quad ( ext{km}) (4)

4.2 Real-Time Temporal Availability Engine

Operating hours are stored as structured JSON records containing daily shift intervals. Because local businesses frequently operate across midnight boundaries (e.g. dhabas or night clinics open from 18:00 to 03:00), simple scalar comparisons fail. Locafy evaluates temporal availability in four steps:

  1. Project current system time into Asia/Kolkata timezone (UTC+05:30) using Intl.DateTimeFormat.
  2. Extract operating day $delta$ and minute-of-day integer $t_{ ext{current}} = 60 cdot ext{hour} + ext{minute} in [0, 1439]$.
  3. Parse open time $t_{ ext{open}}$ and close time $t_{ ext{close}}$.
  4. Evaluate shift condition:
    • Standard Shift ($t_{ ext{open}} le t_{ ext{close}}$): $ ext{isOpen} = (t_{ ext{current}} ge t_{ ext{open}}) land (t_{ ext{current}} le t_{ ext{close}})$.
    • Overnight Shift ($t_{ ext{open}} > t_{ ext{close}}$): $ ext{isOpen} = (t_{ ext{current}} ge t_{ ext{open}}) lor (t_{ ext{current}} le t_{ ext{close}})$.

4.3 Client-Side Interception for Zero-Cost Lead Attribution

Instead of routing customer phone calls or WhatsApp messages through expensive telephony proxy servers (such as Twilio or Exotel virtual numbers), Locafy implements Intent-Interception Proxies. When a consumer clicks "Call Now", "WhatsApp", or "Directions":

User Action (Click Call) --> Intercept DOM Event (event.preventDefault()) --> Asynchronous POST /api/businesses/:id/track { type: 'call' } --> Database logs lead row with timestamp and caller attribution --> Window redirect to native mobile handler: window.location.href = "tel:+91..."

6. Empirical Evaluation & Experimental Results

6.1 Real-World Geographic Dataset

The platform was seeded and tested with a realistic dataset encompassing 49 verified commercial stores, culinary landmarks, and multi-speciality healthcare facilities distributed across 13 major Indian metropolitan regions (Delhi NCR, Mumbai, Bengaluru, Hyderabad, Kolkata, Chennai, Jaipur, Lucknow, Goa, Pune, Ahmedabad, Amritsar, and Chandigarh).

6.2 Payload & Memory Footprint Optimization

Static frontend profiling revealed that the original mockup embedded 86 KB raster images directly into HTML files as inline Base64 data strings. By decoupling assets into standalone PNG files (frontend/assets/logo.png) served with HTTP static caching headers, file payload dropped from 311 KB to 81 KB—representing a 73.9% size reduction.

7. Societal & Economic Impact

In Tier-2, Tier-3, and rural Indian towns, independent service providers (such as electricians, motor mechanics, local bakeries, and clinics) lack the technical literacy and financial capital to maintain paid merchant accounts or buy online advertisement credits. By decoupling local discovery from proprietary cloud platforms, Locafy offers educational institutions, local trade bodies, and municipal governments a turnkey, free-software framework to host community discovery portals that operate permanently without recurring cloud bills.

8. Future Work & Conclusion

Future iterations of this research will explore: (1) integrating quantized local NLP vector embeddings via Transformers.js for semantic conversational querying (e.g. "quiet work cafe with fast wifi and vegan snacks"), (2) decentralized Sybil-resistant review verification using decentralized identifiers (DIDs), and (3) Progressive Web App (PWA) offline Service Worker caching for zero-connectivity catalog browsing in rural markets.

In conclusion, Locafy establishes that full-featured, responsive, and secure hyperlocal business directories with interactive mapping, live temporal evaluation, and lead attribution can be deployed with zero commercial API licensing overhead, demonstrating an accessible paradigm for decentralized digital commerce in developing nations.
